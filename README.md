# LUX Woo Product Sync

Плагін синхронізує товари WooCommerce у зв'язці **один донор → один одержувач**. Базовий режим працює зі стандартним WooCommerce REST API та read-only ключами; встановлювати плагін на донорі не обов'язково.

## Можливості

- постійні UUID для батьківських товарів і варіацій;
- стабільне локальне зіставлення товарів і варіацій за source UUID;
- посторінковий manifest і таблиця лише виявлених змін;
- виявлення нових товарів, змінених і відсутніх варіацій, локальних змін та блокувань;
- п'ять режимів синхронізації: імпорт, основні дані, варіації, відсутні варіації, повний перезапис;
- попередній розрахунок створень, оновлень і видалень для вибраних товарів або всіх товарів, придатних для операції;
- пакетні задачі, журнал результатів та повтор невдалих позицій;
- послідовний чотирикроковий інтерфейс: підключення → аналіз → зміни й дія → журнал;
- захищене зберігання REST-ключів без секретів у вихідному коді.

## Встановлення

1. Встановити й активувати `lux-woo-product-sync` на сайті-одержувачі.
2. На донорі створити WooCommerce REST API key із правами **Read**.
3. На одержувачі відкрити **WooCommerce → Product sync**, вказати URL донора, `ck_...` і `cs_...`.
4. Натиснути **Зберегти й перевірити**. Етап аналізу стане доступним тільки після успішного підключення.
5. Запустити аналіз каталогу, перейти до змін, обрати дію й перевірити її результат перед запуском.

Для віддаленого донора обов'язковий HTTPS. Ключ і секрет зберігаються у WordPress option у зашифрованому вигляді; ключ шифрування походить із WordPress salts.

Перевірка підключення спочатку перевіряє стандартний WooCommerce REST API та валідність ключів. Якщо на донорі додатково встановлений LUX Woo Product Sync, автоматично використовується розширений manifest; інакше модуль переходить у повноцінний `standard_readonly` режим. У цьому режимі стабільні UUID v5 обчислюються з канонічного URL донора, типу об'єкта та його REST ID і зберігаються тільки на одержувачі.

## Дані синхронізації

Основний набір включає назву, slug, статус, описи, ціни, розклад знижки, залишки, податки, доставку, габарити, категорії, теги, атрибути, зображення та дані варіацій. SKU не запитується, не порівнюється і не змінюється.

Для проєктних meta-полів використовується фільтр:

```php
add_filter(
	'lwps_synced_meta_keys',
	static function ( $keys, $context ) {
		if ( 'product' === $context ) {
			$keys[] = '_project_product_field';
		}
		if ( 'variation' === $context ) {
			$keys[] = '_variation_custom_label';
		}
		return $keys;
	},
	10,
	2
);
```

За замовчуванням модуль переносить проєктні поля `_variation_custom_label`, `_variation_discount_percent`, `_lux_variation_flag` і скалярні параметри оформлення gift card. Інші довільні meta-поля не копіюються, щоб не переносити службові дані плагінів та локальні налаштування.

## Захист і відновлення

- У стандартному режимі донора використовуються тільки GET-запити WooCommerce REST API.
- Необов'язкові донорські маршрути розширеного режиму перевіряють WooCommerce REST key та відповідні права.
- Локальні admin-маршрути вимагають WordPress REST nonce та `manage_woocommerce`.
- Видалення відсутніх варіацій доступне лише для повного перезапису та переносить варіацію в кошик.
- Окремий товар можна заблокувати. Масова операція пропустить його, поки адміністратор явно не ввімкне примусове оновлення.
- Кожний товар є окремим елементом задачі. Помилки журналюються і можуть бути перезапущені.
